THE STORY BEHIND SONIVOX
S✦

Built by a developer.
For developers.

SONIVOX was created by Awoyele Victor Ayomide, a developer who wanted voice technology to be easier to access, experiment with, and build into real products.

While building AI assistants and exploring voice-powered applications, I ran into a familiar challenge: useful voice-generation tools can be expensive or difficult for independent developers to integrate. I built SONIVOX to make that first step simpler.

WHY I MADE IT

Because developers like me should be able to experiment, learn, and ship voice-enabled ideas without cost being the first wall they hit.

DEVELOPER DOCUMENTATION

Build with the SONIVOX API

Use this guide to connect your application to your saved SONIVOX voice. Your API key is linked to a voice preset, so a normal speech request only needs the text and language. The API runs on your server and returns a temporary URL for the generated WAV audio.

Before you start

Create a voice profile, then create an API key and attach it to a preset. Copy the key when it is shown; SONIVOX stores a secure hash and cannot reveal the full key again.

1. Keep your API key safe

Send your key in the Authorization header as a Bearer token. Store it in a server-side environment variable such as SONIVOX_API_KEY. Never put it in frontend JavaScript, a public mobile app bundle, a GitHub repository, or a URL. If it is exposed, revoke it and create a replacement.

2. Generate speech

POSThttps://sonivox.onrender.com/v1/speech

Headers

Authorization: Bearer YOUR_SONIVOX_API_KEY
Content-Type: application/json

Request body

{
  "text": "Hello! Welcome to my application.",
  "lang": "eng"
}

Field reference

FieldRequiredDescription
textYesThe words to convert into speech. Send between 1 and 1,000 characters per request.
langNoLanguage code. Defaults to eng (English).
engineNoafrica (default) or silencio. Silencio-2 currently accepts English only.
voice_idUsually noNot needed for a preset-bound key. Only send it when the key owner enabled voice overrides. Older keys without a preset require it.

3. Speech engines and supported languages

The optional engine field selects the speech provider. It defaults to africa, so existing API requests continue to work. Set it to silencio to use Silencio-2 with the selected saved voice sample. The sample is uploaded to the Silencio Hugging Face Space for processing; only use a voice you own or are explicitly authorized to use.

eng Englishyor Yorubahau Hausaibo Igboful Fulfulde

Use the three-letter language codes exactly as shown. For example, use eng, not en. Africa TTS supports all five languages listed above. Silencio-2 currently supports English only; requests using another language with engine: "silencio" are rejected rather than silently routed to another provider.

4. Copy-and-run examples

cURL

curl -X POST "https://sonivox.onrender.com/v1/speech" \
  -H "Authorization: Bearer $SONIVOX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"text":"Hello from my app.","lang":"eng"}'

JavaScript (Node.js server)

const response = await fetch(
  "https://sonivox.onrender.com/v1/speech",
  {
    method: "POST",
    headers: {
      Authorization: `Bearer ${process.env.SONIVOX_API_KEY}`,
      "Content-Type": "application/json"
    },
    body: JSON.stringify({
      text: "Hello from my application.",
      lang: "eng"
    })
  }
);

const result = await response.json();

if (!response.ok) {
  throw new Error(result.detail || "Speech generation failed");
}

console.log(result.audio_url);

Python

Install the HTTP client first with pip install requests, then run this on your backend:

import os
import requests

response = requests.post(
    "https://sonivox.onrender.com/v1/speech",
    headers={
        "Authorization": f"Bearer {os.environ['SONIVOX_API_KEY']}",
        "Content-Type": "application/json",
    },
    json={
        "text": "Hello from my application.",
        "lang": "eng",
    },
    timeout=120,
)

response.raise_for_status()
result = response.json()
print(result["audio_url"])

5. Understand the response

A successful request returns JSON similar to this example:

{
  "id": "generation-uuid",
  "audio_url": "https://...temporary-signed-audio-link...",
  "audio_path": "your-user-id/generations/generation-uuid.wav",
  "duration_ms": 5520,
  "characters_used": 31,
  "preset": "Natural"
}
  • id identifies this generation.
  • audio_url is a signed download/playback link. It expires after one hour, so fetch the audio while the link is valid.
  • audio_path is the private storage location; it is not a public download URL.
  • duration_ms is the generated audio duration in milliseconds, when available.
  • characters_used is the number of text characters charged to the account.
  • preset is the saved voice preset attached to the key.

Use the returned audio_url in your server or client playback flow. For long-term storage, download the file to storage you control before the signed link expires.

6. Voice presets and voice overrides

When you create an API key in SONIVOX, you attach it to one of your saved voice presets. The preset selects the voice profile used by default.

  • Overrides disabled (locked key): requests use the preset's voice. Supplying a different voice_id is rejected.
  • Overrides enabled: the key owner permits requests to supply another voice profile belonging to the same account. If no override is supplied, the preset voice is used.
  • Legacy key: a key created before preset binding must include a valid voice_id.

Voice IDs are account-specific. A key cannot use another user's voice profile.

7. List your available voices

GEThttps://sonivox.onrender.com/v1/voices
curl "https://sonivox.onrender.com/v1/voices" \
  -H "Authorization: Bearer $SONIVOX_API_KEY"

This endpoint returns the voice profiles owned by the account associated with the key. The response is wrapped in a voices array:

{
  "voices": [
    {
      "id": "voice-uuid",
      "name": "My voice",
      "created_at": "2026-11-17T12:00:00Z"
    }
  ]
}

Use it when building a voice picker for keys that allow overrides. The list is scoped to the account that owns the API key.

8. Usage, limits and billing

Developer API speech generation shares the account's monthly SONIVOX character allowance with speech generated in the dashboard. The current Free allowance is 20,000 characters per month, with a maximum of 1,000 characters per request.

  • Successful speech generation counts the characters in the submitted text.
  • Usage is reserved before the upstream voice generation starts.
  • If generation fails, the reservation is released/refunded by the API.
  • OpenRouter or another AI provider's tokens are separate from SONIVOX speech characters. SONIVOX counts the text sent for speech, not the AI model's tokens.
  • Billing is not currently enabled. The allowance and plan shown here are the current MVP configuration.

9. Common errors

HTTP statusMeaningWhat to check
400Text is blank after trimming, or the language code is unsupportedSend non-empty text and use one of eng, yor, hau, ibo or ful.
401Missing, invalid or revoked keyCheck the Bearer header and confirm the key is active.
402Monthly character allowance exhaustedCheck the usage balance in your SONIVOX dashboard.
403Voice override is not permitted, or the sample path is invalidRemove voice_id for a locked preset, or enable overrides on the preset.
404Voice profile or sample not foundUse a voice belonging to the API key's account.
409Linked preset unavailableChoose an active preset and create a new API key if needed.
422Request validation failedCheck that text is present and contains 1–1,000 characters, and that the JSON is valid.
500Unexpected server or upstream request errorRetry cautiously; if it continues, contact SONIVOX support with the request time.
502Generated audio, storage, history or signed-link operation failedRetry after checking service status. Failed generations should release their reserved characters.
503Usage verification failed or the voice provider is busyRetry after a short delay. No speech is returned for this request.
Production checklist

Keep keys on your backend, validate user input, handle non-2xx responses, avoid exposing signed audio links publicly, and add your own user authentication and request-rate limits before allowing public traffic. Never ask an end user to paste your private SONIVOX API key into a browser.
